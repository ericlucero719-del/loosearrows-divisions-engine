CORE CONCEPT
We are building a 10‑division “operations engine” that can run any vendor, any contract, any supply chain. Each division is a module with its own routes, services, types, and controllers, all wired into a shared core engine.

The core engine (src/core/engine.ts) already provides:
- Operator identity (currentOperator)
- A shared in‑memory registry:
  - registry.actions
  - registry.products
  - registry.contracts
- operatorWorkflow(division, actionType) middleware that:
  - logs each request with division, actionType, operator, timestamp, path, payload preview
  - pushes the action into registry.actions
  - attaches req.operatorAction
